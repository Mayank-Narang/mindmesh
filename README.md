## 📖 Overview

**MindMesh** bridges personal knowledge management and AI-assisted research. It unifies rich text, Markdown documentation, and web URL bookmarks into contextual workspaces called **Brains**. Powered by MongoDB Atlas Vector Search, Google Gemini embeddings, and Server-Sent Events (SSE), MindMesh enables semantic exploration, conflict-safe collaborative editing, and cited conversational question-answering strictly grounded in your notes.

---

## 🌟 Key Features

### 1. 📝 Multi-Format Knowledge Ingestion
- **Text & Markdown**: Full Markdown rendering with syntax highlighting, live editing, and preview.
- **URL Enrichment & Bookmarking**: Automated metadata extraction (title, description, publisher, author, OpenGraph image) via an SSRF-safe scraper blocking internal IPs, cloud metadata (`169.254.169.254`), and non-HTTP protocols.
- **Intelligent Chunking**: Long notes are automatically split using sliding windows (~800 characters with 150-character overlap) respecting natural Markdown headings, paragraphs, and sentence boundaries.

### 2. 🔍 Multi-Mode Search Engine
MindMesh provides four distinct retrieval strategies via `POST /api/notes/search`:
- **Semantic Search**: 768-dimensional L2-normalized vector embeddings (`gemini-embedding-001`) with Atlas Vector Search over chunked collections, deduplicated and aggregated by parent note with matching snippet highlights (`chunkIndex`).
- **Keyword Search**: Lexical full-text search using MongoDB text indexing and relevance score ranking.
- **Recency Search**: Chronological sorting by update and creation timestamps.
- **Hybrid Search**: Fuses semantic, lexical, and recency scores using **Reciprocal Rank Fusion (RRF)**:
  $$\text{RRF Score} = \sum_{m \in M} \frac{w_m}{k + \text{rank}_m(d)}$$

### 3. 🤖 Note-Grounded Streaming RAG
- **Server-Sent Events (SSE)** via `POST /api/ai/ask`:
  - `event: sources` — Cited source cards with snippet previews and chunk indexes.
  - `event: message` — Word-by-word streaming answers generated by Gemini.
  - `event: done` — Clean completion signal.
- **Strict Grounding & Citation**: Model answers cite retrieved notes using standard bracket notation (`[1]`, `[2]`), rendered on the frontend as clickable badges that smooth-scroll to cited source cards.

### 4. 👥 Collaborative Editing & Concurrency Control
- **Lease Locks**: 5-minute renewable editing locks (`POST /api/notes/:id/lock`, `POST /api/notes/:id/lock/renew`).
- **Live Draft Soft-Saves**: Real-time autosave (`PUT /api/notes/:id/draft`) that preserves uncommitted edits without overwriting primary note content.
- **Optimistic Concurrency**: Safe commits (`PUT /api/notes/:id`) using `expectedVersion`.
- **Conflict Resolution (HTTP 409)**: Returns the current `serverNote` and the conflicting user's `draft` with 3 recovery choices: reload latest, restore draft, or copy local work.
- **Idle Expiry Cron**: Scheduled background worker releases expired locks every minute while retaining drafts for recovery.
- **Role-Based Access Control (RBAC)**: Fine-grained permissions across notes and brains:
  - `owner`: full read, edit, delete, and share rights.
  - `collaborator`: read and edit rights.
  - `read`: read-only access.

### 5. 🧠 Automated Brain Memory State
- Midnight cron task automatically condenses brain contents into a structured JSON memory summary:
  ```json
  {
    "summary": "AI research repository covering neural networks, backpropagation, and transformer architectures.",
    "noteCount": 18,
    "types": { "text": 8, "markdown": 6, "url": 4 },
    "tags": ["ai", "deep-learning", "rag"],
    "topics": ["Neural Networks", "Attention Mechanisms"],
    "lastActivity": "2026-10-17T22:30:00.000Z"
  }
  ```
- Cached directly on `brain.memoryState` and `brain.description` for instant UI cards.

### 6. 🛡️ Production Hardening
- **Startup Environment Validation**: Strict verification of `MONGODB_URI`, `PORT`, and enforced 32+ character `JWT_SECRET` in production mode.
- **Resilient AI Pipeline**: In-memory LRU embedding cache and exponential backoff retry logic (up to 3 retries for 429 rate limits and 5xx transient server errors).
- **Health Check (`GET /api/health`)**: Reports real-time uptime, MongoDB connection status, and service health.
- **Configurable CORS**: Supports custom production domain allowlists via `CORS_ORIGIN`.

## 🚀 Quick Start

### Prerequisites
- [Node.js](https://nodejs.org/) (v18 or higher)
- [MongoDB Atlas](https://www.mongodb.com/) cluster or local MongoDB instance
- [Google Gemini API Key](https://aistudio.google.com/app/apikey)

---

### Backend Setup

1. **Navigate to the backend directory**:
   ```bash
   cd backend
   ```

2. **Install dependencies**:
   ```bash
   npm install
   ```

3. **Configure environment variables**:
   Create a `.env` file based on `.env.example`:
   ```bash
   cp .env.example .env
   ```
   Fill in your configuration:
   ```ini
   PORT=5000
   NODE_ENV=development
   MONGODB_URI=mongodb+srv://<username>:<password>@<cluster>.mongodb.net/mindmesh
   JWT_SECRET=your-32-character-secure-jwt-secret-here
   GEMINI_API_KEY=your-gemini-api-key
   CORS_ORIGIN=http://localhost:5173
   ```

4. **Start the development server**:
   ```bash
   npm run dev
   ```

---

### Frontend Setup

1. **Navigate to the frontend directory**:
   ```bash
   cd frontend
   ```

2. **Install dependencies**:
   ```bash
   npm install
   ```

3. **Start the Vite development server**:
   ```bash
   npm run dev
   ```

4. **Open your browser**:
   Navigate to `http://localhost:5173`.

## 📡 API Reference

### Authentication & Users
| Method | Endpoint | Description | Auth Required |
|---|---|---|---|
| `POST` | `/api/auth/register` | Register new user account | No |
| `POST` | `/api/auth/login` | Authenticate and obtain JWT | No |
| `GET` | `/api/auth/me` | Fetch authenticated user profile | Yes |

### Brains
| Method | Endpoint | Description | Auth Required |
|---|---|---|---|
| `GET` | `/api/brains` | List accessible brains | Yes |
| `POST` | `/api/brains` | Create a new brain | Yes |
| `GET` | `/api/brains/:id` | Get brain details and notes | Yes |
| `PUT` | `/api/brains/:id` | Update brain metadata | Yes |
| `DELETE` | `/api/brains/:id` | Delete brain and cascade chunks | Yes (Owner) |

### Notes & Collaboration
| Method | Endpoint | Description | Auth Required |
|---|---|---|---|
| `GET` | `/api/notes/:id` | Get note with access check | Yes |
| `POST` | `/api/notes` | Create note and generate chunks | Yes |
| `PUT` | `/api/notes/:id` | Commit update with version check | Yes |
| `DELETE` | `/api/notes/:id` | Delete note and cascade chunks | Yes (Owner) |
| `POST` | `/api/notes/:id/lock` | Acquire 5-minute editing lock | Yes |
| `POST` | `/api/notes/:id/lock/renew` | Renew active editing lock | Yes |
| `PUT` | `/api/notes/:id/draft` | Soft-save in-progress draft | Yes |
| `DELETE` | `/api/notes/:id/lock` | Release editing lock | Yes |

### Search & AI
| Method | Endpoint | Description | Auth Required |
|---|---|---|---|
| `POST` | `/api/notes/search` | Multi-mode search (`semantic`, `keyword`, `recency`, `hybrid`) | Yes |
| `POST` | `/api/ai/ask` | Streamed RAG answer with cited chunks via SSE | Yes |
| `GET` | `/api/health` | System health, MongoDB status, and uptime | No |
